Asynchronous Behavior In JavaScript

How Javascript works

  • Event-Loops (Is handling the both call back queue or Micro Stack queue)
  • Call Stack (The place all code are store before Execution)
  • Call Stack Queue or Macro queue (The Place where all browser APi are store when the Javascript code is running)
  • Micro Stack Queue (The place where all Promises are store when the javascript code is running)

We Know that Javascript is performed synchronous Operations and also Known as single threaded Language. so the before execution of code the code move to Call Stack and after call Stack the code is Executed.So when we need to run javascript in Asynchronous then its work differently so when we use browser APi's for example SetTimeout and setInterval so when code is run these line it cannot be executed same time javascript send this into Call Stack Queue and it can stay there until the the all javascript code is run completely and also all Promises are completed then. so this condition handle by Event loop so Event loop is handling all Asynchronous Function but the Priority is always be Promises after running javascript code the event loop is send all promises into Call stack for execution and then all Micro Queue is completed empty where all promises store.

Step by Step working of javascript

  1. Global Execution Contest
  2. Execution Contest

  4. Call Stack (Also Code Execution)
  5. Event-loops
  6. Call-Stack Queue
